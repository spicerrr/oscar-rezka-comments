# Номинанты «Оскара-2026» глазами пользователей HdRezka

Автоматизированный количественный контент-анализ комментариев к 28 полнометражным фильмам из корпуса номинантов «Оскара-2026».

Проект посвящён пользовательской рецепции фильмов: направленности оценок, выраженным эмоциям, объектам похвалы и критики, особенностям дискуссионных реплик и роли наградной рамки в комментариях.

> https://drive.google.com/file/d/1efz42B7M3fKa_mH0wIVqr9cGXB5hGTxa/view?usp=drive_link

## Ключевые параметры проекта

- полный собранный корпус — **20 660 комментариев**;
- число фильмов — **28**;
- аналитическая выборка — **2555 комментариев**;
- единица анализа — **отдельный комментарий**;
- основной метод — **автоматизированный количественный контент-анализ**;
- дополнительный метод — **элементы количественного фрейм-анализа**;
- локальная модель разметки — **Qwen3:8b** через **Ollama**;
- язык корпуса — преимущественно русский.

## Исследовательский вопрос

**Как различаются валентность, выраженные эмоции и объекты похвалы и критики в комментариях пользователей HdRezka к фильмам из корпуса номинантов «Оскара-2026»?**

### Объект исследования

Публичные комментарии пользователей HdRezka к 28 выбранным полнометражным фильмам.

### Предмет исследования

Текстово выраженная пользовательская рецепция фильмов: направленность оценки, эмоции, объекты похвалы и критики, критерии интерпретации и особенности взаимодействия между пользователями.

Исследование анализирует только то, что выражено в тексте. Оно не позволяет достоверно установить внутреннее эмоциональное состояние автора комментария.

## Состав корпуса

В корпус включены:

- 10 номинантов в категории «Лучший фильм»;

- 5 номинантов в категории «Лучший анимационный фильм»;

- 13 дополнительных полнометражных фильмов из актёрских, сценарных, международной, визуальной, гримёрной и других выбранных категорий.

Документальные и короткометражные фильмы в корпус не включались.

## Сбор данных

Комментарии собирались автоматически со страниц фильмов HdRezka.

Для сбора использовались:

- Python;

- Playwright;

- запросы к интерфейсам загрузки комментариев сайта;

- сохранение данных в формате JSONL;

- контрольные суммы исходных ответов;

- контрольные точки для продолжения работы после сбоя.

Одна строка исходного JSONL-файла соответствует одному комментарию.

Для каждой записи сохранялись:

- идентификаторы и названия фильма;

- URL страницы;

- текст комментария;

- дата публикации;

- число лайков;

- обезличенный идентификатор автора;

- признак ответа другому пользователю;

- идентификатор родительского комментария;

- глубина ветки;

- номер страницы комментариев;

- дата сбора;

- адрес исходного запроса;

- SHA-256 исходного ответа.

## Формирование выборки

Полный корпус был сильно несбалансирован: у наиболее популярных фильмов было более двух тысяч комментариев, а у некоторых картин — несколько десятков.

Чтобы сохранить в анализе все 28 фильмов, использовалась стратифицированная выборка:

- если у фильма было не более 120 комментариев, в выборку включались все;

- если комментариев было больше 120, случайно отбирались 120;

- для воспроизводимости использовалось фиксированное значение `seed = 20260626`.

Итоговый объём выборки — **2555 комментариев**.

### Взвешивание общих результатов

Стратифицированная выборка искусственно увеличивает вклад фильмов с небольшим числом комментариев. Поэтому при расчёте общих долей использовались веса:

```text

вес комментария =

число комментариев фильма в полном корпусе

/

число комментариев фильма в выборке

```

Например, если у фильма в полном корпусе 1200 комментариев, а в выборке 120, один выбранный комментарий представляет десять исходных и получает вес 10.

Веса использовались для восстановления исходного вклада каждого фильма в общую структуру корпуса. При сравнении отдельных фильмов рассчитывались доли внутри каждого фильма.

## Кодировочная схема

Перед автоматической разметкой была разработана формализованная схема категорий.

### Релевантность

Отделялись:

- реакции на фильм;

- просьбы о релизе, переводе или озвучке;

- технические сообщения;

- межпользовательские реплики без оценки фильма;

- ожидания и обсуждение трейлера;

- нерелевантные сообщения.

### Валентность

Валентность — это направленность выраженной оценки:

- `positive`;

- `negative`;

- `mixed`;

- `neutral`;

- `unclear`.

### Эмоции

Кодировались явно выраженные эмоции, в том числе:

- удовольствие;

- восхищение;

- разочарование;

- раздражение или гнев;

- скука;

- грусть или сопереживание;

- страх или напряжение;

- отвращение;

- недоумение;

- веселье.

### Объекты похвалы и критики

Оценка могла быть направлена на:

- фильм в целом;

- сюжет;

- актёрскую игру;

- персонажей;

- визуальный ряд;

- музыку и звук;

- темп или длительность;

- финал;

- экранизацию или франшизу;

- идеологию и репрезентацию;

- наградную достойность.

### Дополнительные категории

Также фиксировались:

- сравнение с другими фильмами;

- отношение к наградной достойности;

- риторический способ выражения;

- интерпретационные фреймы.

Фреймы использовались как разведочный уровень анализа, поскольку их автоматическое кодирование оказалось менее устойчивым, чем определение общей валентности.

## Автоматическая разметка

Разметка выполнялась локально с помощью `qwen3:8b` через Ollama.

Локальная модель была выбрана по нескольким причинам:

- отсутствие расходов на API;

- данные не отправлялись во внешний облачный сервис;

- возможность повторять обработку с одинаковым промптом;

- возможность сохранять прогресс после каждого пакета;

- независимость от внешних лимитов и квот.

Финальная версия скрипта:

- отправляет модели комментарии пакетами;

- требует структурированный ответ;

- проверяет соответствие идентификаторов;

- повторяет запрос при ошибке;

- сохраняет контрольную точку;

- продолжает обработку после остановки без повторной разметки уже готовых записей.

Для финального запуска использовался размер пакета 12 комментариев.

## Проверка устойчивости разметки

Для 100 комментариев была выполнена независимая повторная разметка другой генеративной моделью.

Это не человеческая межкодировочная проверка, а дополнительный модельный аудит.

Наиболее устойчивой категорией оказалась валентность. Более сложные категории — конкретные эмоции и фреймы — интерпретировались осторожно.

## Основные результаты

После взвешивания:

- отрицательная валентность — **43,7%**;

- положительная — **38,6%**;

- смешанная — **6,7%**;

- неясная — **5,7%**;

- нейтральная — **5,3%**.

Основные содержательные выводы:

- негативные реакции немного преобладают, но корпус нельзя описать как сплошной «хейт»;

- фильмы различаются по профилю пользовательских оценок;

- сюжет заметно чаще становится объектом критики, чем похвалы;

- визуальный ряд чаще становится объектом похвалы;

- ответы другим пользователям менее положительны, чем самостоятельные комментарии;

- в **98,4%** реакций наградная достойность не упоминается;

- пользователи обсуждают фильмы прежде всего как зрительский опыт, а не как объекты наградной легитимации.

## Установка

Рекомендуемая версия Python: **3.11–3.13**.

```bash

python -m venv .venv

```

Активация окружения:

```bash

# macOS / Linux

source .venv/bin/activate



# Windows PowerShell

.venv\Scripts\Activate.ps1

```

Установка Python-зависимостей:

```bash

python -m pip install -r requirements.txt

python -m playwright install chromium

```

Ollama устанавливается отдельно. После установки нужно загрузить модель:

```bash

ollama pull qwen3:8b

```

## Воспроизведение конвейера

### 1. Сохранение браузерной сессии

```bash

python scripts/collection/00_capture_session.py

```

Файл `session/storage_state.json` содержит приватные данные браузерной сессии и не должен попадать в Git.

### 2. Разрешение и проверка URL фильмов

```bash

python scripts/collection/01_resolve_urls.py

python scripts/collection/02_probe_comments.py

python scripts/collection/03_validate_urls.py

```

### 3. Сбор комментариев

```bash

python scripts/collection/04_collect_comments.py

```

Полный сырой корпус и ответы сервера не публикуются в репозитории.

### 4. Создание стратифицированной выборки

```bash

python scripts/sampling/04_make_sample_safe.py

```

### 5. Запуск локальной разметки

```bash

python scripts/annotation/06_ollama_coder_v4_fast.py \

--input data/comments_sample_2555.csv \

--job-name sample_2555_v4 \

--batch-size 12

```

При повторном запуске с тем же `job-name` скрипт продолжает работу с контрольной точки.

Для полного перезапуска используется `--restart`, однако этот параметр удаляет прогресс текущего задания.

### 6. Анализ размеченной выборки

```bash

python scripts/analysis/08_analyze_v4.py \

--input data/sample_2555_v4_labeled_ollama.csv \

--output-dir results/analysis_v4 \

--min-film-n 30

```

### 7. Загрузка обложек фильмов

```bash

python scripts/utilities/09_download_posters.py

```

## Что не публикуется

В репозиторий намеренно не включены:

- полный сырой корпус комментариев;

- исходные ответы страниц комментариев;

- cookies и данные авторизованной сессии;

- `.env`;

- соли для хеширования авторов;

- контрольные точки Ollama;

- журналы выполнения;

- частичные и аварийные выгрузки;

- локальные абсолютные пути;

- старые версии скриптов и дубликаты проекта.

## Ограничения

- пользователи HdRezka являются самоотобранной аудиторией;

- результаты нельзя переносить на всех зрителей;

- один пользователь мог оставить несколько комментариев;

- ответы другим пользователям могут зависеть от контекста предыдущих реплик;

- автоматическая разметка не заменяет человеческое кодирование;

- наиболее надёжны укрупнённые категории валентности и объектов оценки;

- эмоции и фреймы требуют осторожной интерпретации;

- анализ фиксирует публично выраженную реакцию, а не внутреннее состояние автора.

## Этические и технические меры

- имена пользователей не использовались в аналитическом датасете;

- авторы представлены обезличенными идентификаторами;

- приватные данные браузерной сессии исключены;

- полный сырой корпус не публикуется;

- происхождение файлов зафиксировано в `docs/PROVENANCE.csv`;

- структура публичного репозитория собрана по белому списку файлов.
